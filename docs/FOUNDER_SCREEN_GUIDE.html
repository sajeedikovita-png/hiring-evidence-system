Before you show anyone

Say this

“You give it a job and a resume. It gives you back one clear report: what the person has proven, what is missing, and what to ask in the interview. A person still makes the final choice — the software never decides for you.”

How to open the app

Three steps

  1. Open a terminal in the project folder.
  2. Type npm run dev
  3. Open http://localhost:3000

If port 3000 is busy

It opens on http://localhost:3001 instead. Both are the same app — just use whichever address the terminal shows you.

The three marks used all through this guide

works Does what it should. Safe to show. not built On purpose, not real yet. Not broken. broken A real problem: an error or wrong behaviour.

The golden word rule (very important)

When you talk about this product, and everywhere in the app, we never use words that sound like the computer made the choice by itself, that name someone the top pick, that say the software throws anyone out on its own, or that promise hiring is completely free of bias.

We say instead: evidence found, evidence missing, needs verification, human review required, strong evidence, decision reason required. The whole product is built on one idea: the computer shows the proof, a person makes the call.

The full written list of words to avoid is in docs/UX_COPY_RULES.md. Please read it before writing any new copy.

Two things you will see on many screens

1) The yellow “Seed fallback mode / Missing env vars” box. On the inside screens you will see a yellow box asking to add some settings. Do not worry. It is a note for the developer only — it means the app is running on built-in demo data instead of a real database. It is not an error, and it does not appear in the real live version. What happens when you drop files (this really works)

  • A good PDF or DOCX → row shows Uploaded / Report ready and gets a “View report” link. works
  • A wrong type (like a .png or .zip) → row shows Failed — “Unsupported file type”. works
  • A file over 10 MB → row shows Failed — “File too large”. works
Be clear-eyed about this (say it honestly if asked): the report made from an upload is scripted from the file’s category, not read from the real words in the file yet. That is why every uploaded report carries a “Demo preview report” banner. Real reading of the document by AI is the next build step. Also, uploaded files and their reports disappear when you refresh the page — the page only remembers them until you refresh. This is expected. not built
Say this

“Drop in a pile of resumes — good PDFs and Word files are accepted, wrong or huge files are refused, and each good one gets its own evidence report.”

The Human Decision panel — the part that really works

This is the strongest “it actually works” moment. Try it live:

  1. Pick a choice (for example Shortlist for interview) but leave the reason box empty and press “Save decision”.
  2. It blocks you and says “Decision reason required.” works
  3. Now type a real reason and press “Save decision”.
  4. It accepts and says “Recruiter decision recorded.” works
  5. If you refresh, the saved decision is gone — expected here, there is no real database yet. The check and the save action still run for real. not built
