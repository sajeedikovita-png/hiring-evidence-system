## Cross-batch recruiter observations

- All 20 PDFs are explicitly fictional test data. Every file states that work samples, references and supporting materials are available on request, but none supplies an inspectable repository, employer reference or signed acceptance record.
- The strongest recurring source evidence is concrete implementation scope plus a named interaction or handover artefact. Those claims still need human verification of authorship, dates, context and outcome.
- The matrix is generally conservative. The clearest interpretation issue is that the combined JS/TS criterion hides which language has evidence: Sam lacks shipped TypeScript, whereas Casey and Taylor describe TypeScript but not specific JavaScript delivery. Coursework/prototype React evidence (Morgan and Peyton) must remain visibly distinct from production delivery. No automatic status changes are warranted from these observations.
- A recruiter should preserve the distinction between framework-adjacent work and the requested browser React role: Vue, Angular, React Native, backend TypeScript and React test automation do not by themselves establish browser React delivery.
- The source review cannot validate report persistence, report text, batch grouping, company isolation, public evidence, or any live UI behavior. Those require separate product checks.
